# Трек 3: Логистика и закупки (Кейс Электрокомплект — «Умный Закуп» и пополнение склада)

> **Бизнес-кейс:** Автоматизация работы менеджера по закупкам компании «Электрокомплект» (крупный дистрибьютор электротехники).  
> **Входные данные:** Реальные выгрузки из 1С по двум ключевым поставщикам (**IEK** и **Systeme Electric**):
> - Ежемесячные продажи за 2 года в штуках и деньгах.
> - Текущие остатки на складах и товар в пути на 22.09.2026.
> - Коэффициенты сезонности и кванты поставок (MOQ — минимальная партия, кратность упаковки).
> - Сроки доставки (Lead Time: 15–45 дней в зависимости от завода).  
> **Цель:** Спрогнозировать дефицит товаров, отфильтровать разовые аномальные всплески спроса и автоматически сформировать оптимальный заказ поставщику с минимальной заморозкой оборотного капитала.

- **Архитектура:** Серверный препроцессинг данных + легковесный Web Client (PWA)

- **Объяснимый ИИ:** При клике на позицию заказа ИИ объясняет решение человеческим языком: *«Рекомендуется заказать 480 шт. (8 упаковок по 60 шт.), так как через 18 дней ожидается обнуление остатка с учетом сезонного роста спроса на 22%»*.

## 3. 🥉 GrimStack (3 место)

### Стек технологий
- **Backend:** Python 3.11+, **FastAPI**, Pydantic v2, Uvicorn, Pandas
- **Frontend:** Современный SPA-интерфейс, ApexCharts (раздельные чарты количеств и денег)
- **ИИ-провайдер:** Поддержка **NVIDIA NIM** (локальная модель Laya) + OpenAI API
- **База данных:** SQLite для хранения утвержденных согласований

### Структура файлов
```text
├── app/
│   ├── api/routes.py              # Эндпоинты заказов, сравнения и backtest
│   ├── engine/                    # Конвейер очистки данных и прогноза
│   │   ├── cleaning.py            # Очистка периодов дефицита (out-of-stock)
│   │   └── forecast.py            # Модель прогноза спроса
│   ├── ai/                        # Интеграция с LLM и NVIDIA NIM
│   └── contracts.py               # Pydantic контракты ядро ↔ фронт
└── Dockerfile                     # Сборка моносервиса
```

### Главные фишки
- **Симуляция сценариев «Что если» (What-If Analysis):** Возможность подвинуть ползунок: *«Что если завод задержит поставку на 14 дней?»* — система мгновенно пересчитывает риски кассового разрыва и упущенной выгоды.
- **Очистка данных от месяцев дефицита:** Если товара не было на складе 20 дней из 30, продажи за этот месяц были нулевыми не из-за отсутствия спроса, а из-за отсутствия товара. GrimStack восстанавливал реальный спрос методом нормализации рабочих дней.

## 💡 Выводы для VibeStack:

1. **Vercel Deploy в первые 2 часа:**  
   Пока другие настраивают Docker на локальном ноутбуке, работающий URL в Vercel дает гигантское преимущество на питче.
2. **Интеграция с мессенджерами (WhatsApp/Telegram):**  
   Для B2B-заказчиков возможность отправить готовый заказ в WhatsApp поставщику — это вау-эффект.
3. **Восстановление спроса при Out-of-Stock:**  
   Классическая ошибка начинающих логистов — прогнозировать нулевые продажи, когда на складе просто не было товара. Очистка дефицитных периодов обязательна.
