# Трек 8: Образование (Кейс Challenge Hub — Платформа студенческих команд и бизнеса)

> **Бизнес-кейс:** Создание платформы «Challenge Hub», соединяющей реальные бизнес-задачи предпринимателей и проектные студенческие IT-команды.  
> **Проблема:** Предприниматели не умеют писать технические задания (пишут «хочу сайт как Каспи»), а студенты не понимают требований и срывают сроки.  
> **Цель:**
> - AI-интервьюер проводит бриф заказчика (задает 3–5 уточняющих вопросов).
> - Автоматически формирует структурированную карточку задачи (ТЗ, стек, артефакты, критерии приемки).
> - Присваивает прозрачный индекс готовности ТЗ (Readiness Score).
> - Матчит задачу с профилями студенческих команд и ведет поэтапный трекинг с начислением баллов/XP.

## 1. 🥇 GhostTech (1 место)

### Стек технологий
- **Backend:** Python 3.12, **FastAPI**, SQLAlchemy, Alembic, SQLite, пакетный менеджер **uv**
- **Frontend:** Адаптивный веб-интерфейс на HTML5/CSS3/Vanilla JS (три языка: RU / KZ / EN)
- **Управление сборкой:** `Makefile`

### Архитектура и киллер-фичи:
1. **Разделение рейтингов (Readiness vs Progress):** Рейтинг готовности ТЗ (насколько качественно бизнес описал задачу) строго отделен от рейтинга студенческой команды (очки за этапы 10/20/30 начисляются только после физического подтверждения кода заказчиком).
2. **Анти-фрод фильтр (Security Validator):** Сервер автоматически сканировал текст задач на предмет фишинга, сомнительных номеров телефонов, спам-ссылок и подозрительных требований бесплатных тестовых заданий.
3. **Квоты на токены:** Защита от бесконечного спама в диалоге с ИИ — жесткий лимит на 5 уточняющих вопросов в рамках одного брифа.

## 2. 🥈 Larda (2 место)

### Стек технологий
- **Backend:** **Go (Gin)**, GORM, **PostgreSQL 16**
- **Frontend:** **React 19**, React Router 7, **Vite 8**, TypeScript, Docker Compose
- **Тесты:** Playwright (автоматические E2E-тесты интерфейса)
- **Модели:** `gpt-6-luna`, `gpt-4o-mini`

### Главная инженерная фишка: Очередь задач без Redis
- Чтобы не тратить время на развертывание Redis и Celery за 5 часов, команда реализовала **асинхронную очередь задач прямо в PostgreSQL** с помощью механизма `SELECT ... FOR UPDATE SKIP LOCKED`.
- Фоновый воркер на Go параллельно опрашивал базу и запускал генерацию ТЗ через LLM, не блокируя UI пользователя.

## 3. 🥉 archibalt (3 место)

### Стек технологий
- **Backend & DB:** Go, PostgreSQL 16, Docker Compose, Makefile
- **Frontend:** React, Vite, TypeScript
- **Модели:** `gpt-6-sol`, `gpt-5.4-mini`

### Самый образцовый процесс AI-разработки (245 коммитов):
Команда построила автономный пайплайн с виртуальными ролями:
- **Роль `Red Team Judge`:** Отдельный агент, который специально пытался сломать карточку ТЗ заказчика, вводя бессмысленные и токсичные запросы, и проверял реакцию валидатора.
- **Генерация визуального концепта:** Помимо текста ТЗ, система автоматически создавала схематический мокап будущего проекта.
- **Скилл `jury-review`:** В репозитории был заложен отдельный скрипт тестирования для жюри с матрицей соответствия требованиям хакатона.

## 💡 Выводы для VibeStack:
1. **PostgreSQL как очередь задач:** Механизм `FOR UPDATE SKIP LOCKED` позволяет выкинуть Redis на хакатоне и сэкономить 30 минут настройки.
2. **Четкие этапы сдачи (Milestones):** Взаимодействие бизнеса и исполнителей строится вокруг пошагового согласования (10% ТЗ → 30% прототип → 60% MVP → 100% релиз).
