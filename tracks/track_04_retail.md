# Трек 4: Торговля (Кейс Электрокомплект — Комплектование корзины и AI-консультант)

> **Бизнес-кейс:** Создание интеллектуального консультанта по каталогу электротехнической продукции интернет-магазина **ekt.kz**.  
> **Входные данные:** Каталог более чем на 10 000 SKU (автоматы, кабели, шкафы, розетки, трансформаторы), прайс-листы, городские остатки на складах и технические паспорта.  
> **Цель:** Клиент обращается на естественном языке, скидывает фото щитка, маркировку или список из сметы. AI-консультант должен:
> - Распознать точные характеристики (мощность, ампераж, фазность).
> - Проверить реальные складские остатки и цены.
> - Предложить совместимые аналоги, если нужной позиции нет.
> - Сформировать согласованную спецификацию и положить товар в корзину **только после подтверждения пользователя**.

## 1. 🥇 Zhigitter (1 место)

### Стек технологий
- **Frontend & App:** **Next.js 16 (Canary / App Router)**, **React 19**, **Tailwind CSS 4**, TypeScript
- **ИИ-модели:** `gpt-4.1-mini` (OpenAI Responses API + Multimodal Vision)
- **Деплой:** **Vercel** (публичная ссылка в README)
- **Конфигурация агентов:** `AGENTS.md` + `CLAUDE.md`

### Архитектура и структура файлов
```text
├── AGENTS.md                  # Правила для агентов (Zod, FSD-слои, правила корзины)
├── CLAUDE.md                  # Указатель на AGENTS.md для Claude Code
├── src/
│   ├── app/                   # Next.js App Router (каталог, чат, корзина, спецификация)
│   ├── components/            # UI-компоненты карточек товаров, подбора аналогов
│   └── lib/
│       ├── ai/                # Мультимодальный парсер фото и текста
│       └── catalog/           # Поисковый движок по базе ekt.kz с фильтрами
└── README.md                  # Инструкция запуска и ссылка на Vercel
```

### Как вайб-кодили и киллер-фичи:
1. **Мультимодальный поиск по фото:** Покупатель загружает фотографию старого перегоревшего автомата в щитке — модель распознает модель, номинал (например, 16А C-характеристика) и мгновенно находит современный аналог в наличии.
2. **Обработка возражений:** В систему заложены готовые сценарии работы с сомнениями клиента: *«почему так дорого?»*, *«подойдет ли к моему кабелю?»*, *«нужно срочно сегодня»*.
3. **Защита от несоответствий в каталоге:** Команда нашла в выданном каталоге баг (у товара 027228 в описании было 160А, а в названии 250А). Их система блокировала добавление такого противоречивого товара и выводила предупреждение.
4. **Автономность без ключей:** Жюри могло тестировать Vercel-демоверсию со встроенными моками без необходимости вводить личные API-ключи.

## 2. 🥈 SAQ Digital (2 место)

### Стек технологий
- **Backend:** Node.js, Express, **Zod** (строгая валидация схем), Vitest
- **Frontend:** React, TypeScript, Vite, Tailwind CSS
- **DevOps:** Docker Compose, Nginx, скрипт `start.cmd`

### Архитектура «Серверного контроля»:
- **Жёсткий барьер для LLM:** Модель `gpt-4.1-mini` используется **только для извлечения намерений и характеристик** из речи клиента. 
- Модель **не имеет права** сама генерировать цены, проверять остатки или добавлять товары в корзину текстом.
- Корзина и остатки формируются детерминированным сервером на Express через строгие Zod-схемы. Если клиент не нажал физическую кнопку «Подтвердить», товар в заказ не попадает.

## 3. 🥉 Survae (3 место)

### Стек технологий
- **Backend:** Python 3.11, **FastAPI**, Pydantic v2, HTTPX
- **Парсинг документов:** `pypdf`, `python-docx`, `openpyxl`, `xlrd`, `Pillow`
- **Тесты:** 173 Python-теста + 6 E2E фронтенд-тестов

### Главная фишка: Разбор PDF/Excel смет
- Клиент загружает строительную смету или ведомость материалов в PDF/DOCX/Excel.
- Бэкенд на Python парсит таблицу, сопоставляет неточные наименования прорабов с номенклатурой ekt.kz и собирает готовую спецификацию со статусами наличия по филиалам городов.

## 💡 Выводы для VibeStack:
1. **Мультимодальность (Vision) выигрывает e-commerce кейсы:** Возможность распознавать фото оборудования и сканы смет производит колоссальный эффект на бизнес-жюри.
